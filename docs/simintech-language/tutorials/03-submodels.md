# Туториал 3: Субмодели — создаём макроблоки

Учимся создавать иерархические схемы с помощью субмоделей в SimInTech.

## Что ты узнаешь

- Зачем нужны субмодели
- Как создать субмодель из группы блоков
- Как задать входы/выходы субмодели
- Как использовать субмодель как обычный блок

## Зачем нужны субмодели

Когда схема разрастается до десятков блоков, разобраться в ней становится трудно. Субмодели позволяют:

- **Группировать логически связанные блоки** (например, весь регулятор в один блок)
- **Создавать иерархию** — субмодели внутри субмоделей
- **Переиспользовать** — один раз создал, используй многократно
- **Упрощать** — верхний уровень схемы показывает только основные связи

## Шаг 1: Создай субмодель

Мы создадим субмодель ПИД-регулятора из предыдущих уроков.

1. Создай новую схему (Ctrl+N)
2. Размести блоки ПИД-регулятора:
   - 2 Сумматора
   - 1 Интегратор
   - 3 Усилителя (Kp, Ki, Kd)
   - 1 Ограничитель
3. Выдели все блоки (рамкой)
4. Правый клик → **«Создать субмодель»**
5. Введи имя: `PID_Controller`

## Шаг 2: Настрой порты субмодели

После создания откроется содержимое субмодели. На границе будут автоматически созданы:

- **Вход/Выход SubModel** — для всех связей, которые вели наружу
- Их нужно переименовать

Переименуй порты:
- Порты подключения уставки → `SP` (SetPoint)
- Порты обратной связи → `FB` (FeedBack)
- Выход регулятора → `OUT` (Control output)

Для этого кликни на порт → F2 → введи имя.

## Шаг 3: Используй субмодель

Теперь вернись на верхний уровень схемы (двойной клик на пустом месте). Ты увидишь один блок с именем `PID_Controller` и тремя портами.

Подключи его как обычный блок:
```
Уставка → PID_Controller.SP
Датчик  → PID_Controller.FB
PID_Controller.OUT → Объект_управления
```

## Создание субмодели через код

Ту же субмодель можно создать программно:

```simintech
// Файл: PID_sm.prj (содержимое субмодели)

// Внешние порты
function PID_Controller
  input:
    double SP;
    double FB;
  output:
    double OUT;
  var:
    double Kp = 2.0;
    double Ki = 0.5;
    double Kd = 0.1;
    double error;
    double integral = 0.0;
    double prevError = 0.0;
    double pTerm, iTerm, dTerm;
    double output;
    double outMin = 0.0;
    double outMax = 100.0;
    bool saturated = false;
    double dt;

  begin:
    dt = getStepSize();
    error = SP - FB;

    // P
    pTerm = Kp * error;

    // I (с анти-windup)
    if not saturated then
      integral = integral + error * dt;
    end_if;
    iTerm = Ki * integral;

    // D
    dTerm = Kd * (error - prevError) / dt;

    // Сумма
    output = pTerm + iTerm + dTerm;

    // Ограничение
    if output > outMax then
      output = outMax;
      saturated = true;
    elsif output < outMin then
      output = outMin;
      saturated = true;
    else
      saturated = false;
    end_if;

    OUT = output;
    prevError = error;
  end;
```

## Гнездование субмоделей

Субмодели могут содержать другие субмодели. Пример:

```
├── Верхний уровень (схема завода)
│   ├── Субмодель: Реактор
│   │   ├── Субмодель: PID_Температура
│   │   │   ├── Блок: Сумматор
│   │   │   ├── Блок: Интегратор
│   │   │   └── Блок: Усилители
│   │   ├── Субмодель: PID_Давление
│   │   └── Блок: Клапан
│   └── Субмодель: Теплообменник
│       ├── Блоки тепловой модели
│       └── Субмодель: PID_Расход
```

## Передача параметров в субмодель

Параметры субмодели настраиваются через диалог свойств (двойной клик по субмодели на верхнем уровне).

Создай параметры:
1. Открой субмодель
2. Правый клик → «Параметры субмодели»
3. Добавь:
   - `Kp` (double, 2.0)
   - `Ki` (double, 0.5)
   - `Kd` (double, 0.1)

Внутри субмодели используй `getParameter("Kp")`:

```simintech
var:
  double Kp;
init:
  Kp = getParameter("Kp");
```

## Преимущества иерархического подхода

1. **Повторное использование**: создай библиотеку типовых субмоделей (ПИД-регуляторы, фильтры, приводы) и используй в разных проектах
2. **Удобство отладки**: отлаживай каждую субмодель отдельно
3. **Командная работа**: разные инженеры разрабатывают разные субмодели
4. **Документирование**: структура субмоделей отражает архитектуру системы

## Практическое задание

Создай иерархическую модель системы управления температурой:

1. **Уровень 1**: Схема с блоками Уставка, ПИД (субмодель), Объект, Датчик, График
2. **Уровень 2 (субмодель ПИД)**: Сумматор, Интегратор, 3 усилителя, Ограничитель
3. **Уровень 2 (субмодель Объект)**: Передаточная функция 1/(10s+1) + блок возмущения
4. **Параметры субмоделей**: Kp, Ki, Kd настраиваются с верхнего уровня

## Проверь себя

1. Как создать субмодель? → Выделить блоки → правый клик → «Создать субмодель»
2. Как попасть внутрь субмодели? → Двойной клик по блоку субмодели
3. Как настроить порты? → Клик на порт → F2 → новое имя
4. Как передать параметр в субмодель? → getParameter("имя")
5. Можно ли вложить субмодель в субмодель? → Да, без ограничений

## Типичные ошибки

- **Забыл создать порты**: субмодель не имеет связи с внешним миром — проверь, что все нужные порты есть на границе
- **Дублирование имён**: внутри субмодели и на верхнем уровне не должно быть блоков с одинаковыми именами
- **Циклическая субмодель**: субмодель не должна ссылаться сама на себя (напрямую или через цепочку)
- **Параметры не обновляются**: после изменения параметров субмодели перезапусти моделирование
