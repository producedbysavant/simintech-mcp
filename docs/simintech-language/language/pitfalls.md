# Типичные ошибки в SimInTech и их решения

Сборник распространённых проблем, с которыми сталкиваются пользователи SimInTech, и способы их решения.
Основан на практическом опыте кодогенерации в C.

## 1. «Программа не компилируется»

### 1.1. Пропущена точка с запятой

**Ошибка:**
```simintech
y = a + b   // забыта ;
z = c + d;
```

**Решение:** Каждый оператор должен заканчиваться `;`.

### 1.2. Несоответствие begin/end

**Ошибка:**
```simintech
if x > 0 then
    y = 1;
// забыт end;
```

**Решение:** Каждый `if...then` с блоком завершается `end;`.

### 1.3. Использование C-подобных операторов

**Ошибка:**
```simintech
if (x == 0) { y = 1; }        // == и {} — синтаксическая ошибка
if (a != b) || (c != d) { }   // != и || — синтаксическая ошибка
```

**Решение:** SimInTech использует Pascal-подобный синтаксис:
```simintech
if x = 0 then begin y = 1; end;
if (a <> b) or (c <> d) then begin end;
```

### 1.4. Список имён с одним типом в var

**Ошибка:**
```simintech
var a, b, c: double;      // НЕДОПУСТИМО
var i, j, k: integer;     // НЕДОПУСТИМО
```

**Решение:** Каждая переменная с явным типом:
```simintech
var
    a: double,
    b: double,
    c: double;
```

## 2. Ошибки времени выполнения

### 2.1. Деление на ноль

**Проблема:** `y = 1.0 / x` при `x = 0` даёт ошибку кодогенерации.

**Решение:**
```simintech
if abs(x) > 1e-12 then
    y = 1.0 / x
else
    y = 0;
```
Или: `y = 1.0 / (x + 1e-12);`

### 2.2. Переполнение интегратора

**Проблема:** Интегратор накапливает ошибку и уходит в бесконечность.

**Симптомы:** На графике — линейно растущий сигнал.

**Решение:** Ограничение выхода + anti-windup:
```simintech
state = state + u * dt;
if state > maxState then
    state = maxState
else if state < -maxState then
    state = -maxState;
```

### 2.3. Выход за границы массива

**Ошибка:**
```simintech
var arr[5]: array;
arr[5] = 10.0;  // индекс 5 вне диапазона [1..5]
```

**Решение:** Индексы массива от 1 до N. Проверяйте границы:
```simintech
if (idx >= 1) and (idx <= lenS) then
    arr[idx] = 10.0;
```

### 2.4. Арифметика внутри индексов

**Ошибка:**
```simintech
val = arr[cur_i - 1];   // может не транслироваться в C
```

**Решение:** Выносите индекс в отдельную переменную:
```simintech
prev_i = cur_i - 1;
if prev_i < 1 then prev_i = 1;
val = arr[prev_i];
```

## 3. Ошибки кодогенерации (F9)

### 3.1. Оператор `#` (размножение числа)

**Проблема:** Не транслируется в C.

**Решение:**
```simintech
// НЕПРАВИЛЬНО:
v = 3#0.1;

// ПРАВИЛЬНО:
for (idx = 1, 3) do v[idx] = 0.1;
```

### 3.2. Оператор `&` (конкатенация векторов)

**Проблема:** Не транслируется в C.

**Решение:**
```simintech
// НЕПРАВИЛЬНО:
R = R & [value];

// ПРАВИЛЬНО:
lenR = lenR + 1;
R[lenR] = value;
```

### 3.3. Оператор `..` (интервал)

**Проблема:** Не транслируется в C.

**Решение:**
```simintech
// НЕПРАВИЛЬНО:
a = 1..5;

// ПРАВИЛЬНО:
for (idx = 1, 5) do a[idx] = idx;
```

### 3.4. Конфликт имён с `i`, `j`, `c`

**Проблема:** Транслятор добавляет в C-код локальные переменные `i`, `j`, `c` для циклов. Если пользователь объявил свою переменную с таким именем — ошибка компиляции C.

**Решение:** Используйте осмысленные имена: `idx`, `wagon`, `row_idx`, `col_idx`.

### 3.5. Динамические массивы

**Проблема:** `var R: array;` без размера — не транслируется.

**Решение:** Всегда указывайте размер с запасом:
```simintech
const MAX_PROFILE = 2000;
var
    R[MAX_PROFILE]: array,
    lenR: integer;
```

### 3.6. `seterrorstr` не транслируется

**Решение:** Используйте выходные сигналы для диагностики:
```simintech
output error_code: integer;
error_code = 1;   // код ошибки
exit;
```

## 4. Ошибки моделирования

### 4.1. Расходящееся решение

**Проблема:** Система «взрывается» — значения уходят в бесконечность.

**Решение:**
1. Уменьшите шаг моделирования в 10 раз
2. Проверьте знаки обратных связей
3. Для жёстких систем используйте неявные методы интегрирования

### 4.2. Алиасинг (ложные частоты)

**Проблема:** На графике отображается сигнал с частотой, которой нет в системе.

**Решение:** Уменьшите шаг моделирования: `dt < 1 / (2 * f_max)`.

### 4.3. Алгебраическая петля

**Проблема:** Сигнал проходит через цепочку блоков и возвращается на вход без задержки.

**Решение:** Добавьте интегратор в контур или блок «Задержка» (Unit Delay).

## 5. Ошибки логики

### 5.1. Интегральное насыщение (windup)

**Проблема:** После выхода из ограничения регулятор долго «приходит в себя».

**Решение:** Останавливайте интегрирование при насыщении:
```simintech
if not saturated then
    integral = integral + error * dt;
```

### 5.2. Дребезг (chattering) релейного регулятора

**Решение:** Добавьте гистерезис:
```simintech
if u > threshold + hysteresis/2.0 then
    y = 1.0
else if u < threshold - hysteresis/2.0 then
    y = 0.0;
```

### 5.3. Порядок вычислений в условиях

**Ошибка:**
```simintech
if a > 0 and b < 10 then ...  // порядок вычислений непредсказуем
```

**Решение:** Скобки обязательны:
```simintech
if (a > 0) and (b < 10) then ...
```

## 6. Проблемы с производительностью

- Слишком малый шаг моделирования → увеличьте (в разумных пределах)
- Запись всех сигналов → отключите промежуточные
- Включена анимация → отключите визуализацию
- Файл данных слишком большой → пишите каждый 10-й или 100-й шаг

## 7. Ошибки с памятью и массивами

### 7.1. Копирование массивов

**Ошибка:**
```simintech
R = Curve_radiuses;   // прямое присваивание не транслируется
```

**Решение:**
```simintech
for (idx = 1, lenR) do R[idx] = Curve_radiuses[idx];
```

### 7.2. Передача строки матрицы

**Решение:** Только поэлементно:
```simintech
for (col_idx = 1, NPAR) do row[col_idx] = M[wagon, col_idx];
```

### 7.3. Матричные операции (`*`, `\`, `./`)

**Проблема:** Не транслируются в кодогенераторе.

**Решение:** Реализуйте умножение матриц вручную через циклы.

## 8. Ошибки округления

### 8.1. Сравнение с нулём

**Ошибка:**
```simintech
if x = 0.0 then  // может не сработать из-за погрешности
```

**Решение:**
```simintech
if abs(x) < 1e-9 then
```

### 8.2. Накопление погрешности

**Решение:**
- Используйте метод Рунге-Кутты вместо Эйлера
- Периодически сбрасывайте состояние (если позволяет физика)
- Используйте `double` (в SimInTech по умолчанию)

## Чек-лист перед запуском кодогенерации (F9)

- [ ] Нет переменных с именами `i`, `j`, `c`
- [ ] Все переменные с явным типом: `var x: double;`
- [ ] Операторы сравнения: `=` и `<>` (НЕ `==` и `!=`)
- [ ] Логика: `and`, `or`, `not` (НЕ `&&`, `||`, `!`)
- [ ] Блоки: `begin..end;` (НЕ `{..}`)
- [ ] Нет `#`, `&`, `..` в коде
- [ ] Массивы со статическим размером: `var R[MAX]: array;`
- [ ] Нет `seterrorstr`
- [ ] Нет прямого присваивания массивов
- [ ] Индексы — переменные, не выражения: `prev_i = cur_i - 1; val = arr[prev_i];`
- [ ] Деление защищено: `abs(x) > 1e-12` или `x + 1e-12`
- [ ] Входные массивы проверены на `lengthofm(arr) > 0`
