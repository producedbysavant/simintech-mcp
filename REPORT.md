# Отчёт о разработке simintech-api

Библиотека для программного управления SimInTech через COM API. Разработана
в 6 фаз + финальный этап тестирования/документирования.

### Интеграционные тесты (реальный COM, Windows)

```
$ pytest tests/integration -m integration
# Итог: 3 passed, 2 skipped
```

Запускаются на Windows с `mmain.exe /regserver`. В ходе итераций на реальном
COM-сервере найдены и исправлены 4 бага (см. §4).

**Статус на 2026-08-18: 3 passed, 2 skipped — падений нет.** Пропускаются:
- `test_open_project_signals` — демо-модель не имеет внешних (обменных)
  сигналов, `GetProjectSignalList` пуст (корректное поведение COM);
- `test_read_write_signal` — см. §4, пункт о сигналах.

**Решение для доступа к сигналам блоков (реализовано):** внутренние сигналы
блоков НЕ попадают в `GetProjectSignalList` (он возвращает только обменные
сигналы блоков «Вход/Выход алгоритма»). Для доступа к ним реализован парсер
XML-представления проекта (`utils/xprt_signals.py`): `Project.list_signals()`
при пустом COM-списке экспортирует проект в `.xprt` и извлекает имена
блоков (в SimInTech сигнал блока именуется по имени блока). Проверено на
реальном `.xprt` (1042 имени извлечено, графические объекты отфильтрованы).

## 2. Описание демо-моделей

### Модель 1: «Усилитель сигнала» (`examples/model1_amplifier.py`)
- Схема: `Синусоида (1 Гц) → Усилитель (×2.5)`.
- Расчёт на 10 с, сохранение в `model1_amplifier.xprt`.

### Модель 2: «ПИД-регулятор» (`examples/model2_pid.py`)
- `Ступенька (уставка 1) → Сумматор ошибки → ПИД (Kp=1, Ki=0.5, Kd=0.1) →
  Интегратор (объект)` с обратной связью выхода на вход сумматора (−1).
- Шаговый расчёт 20 с, переходная характеристика в `model2_pid.csv`.

### Модель 3: «Многокомпонентная система» (`examples/model3_complex.py`)
- 12 блоков, 14 перекрёстных связей.
- `LayeredPlacer` расставляет без наложений (проверено: 0 наложений).
- `AStarRouter` трассирует линии в обход блоков (проверено: 14/14 линий,
  0 опорных точек внутри блоков).
- Сохранение в `model3_complex.xprt`.

| Сценарий | Результат |
|---|---|
| Placer, линейная цепочка 200 блоков | < 0.1 с |
| Placer, бинарное дерево 127 блоков | < 0.1 с |

моделей.

## 4. Проблемы, найденные в ходе интеграционного тестирования, и решения

| Проблема | Причина | Решение |
|---|---|---|
| `ImportError: _to_descriptor` | функция была в `com_client.py`, а импортировалась из `converters.py` | перенесена в `converters.py` |
| `list_signals()` возвращал пустой список | `GetProjectSignalList` требует `ProjectStart` (модель компилируется) | добавлено предупреждение в docstring, тесты вызывают `sim.start()` |
| после тестов оставался висеть `mmain.exe` | COM-сервер out-of-proc не закрывался | `COMClient.shutdown()`: PID-трекинг + `taskkill`; завершается только процесс, порождённый клиентом |
| router не находил путь при блоках на краю сетки | вылет из порта (20px) попадал в margin-зону блока (20px) | вылет увеличен до `2×grid_size` |
| перекрёстные линии блокировали друг друга | точки линий помечались как жёсткие препятствия | линии не делаются препятствиями — A* обходит блоки, линии могут пересекаться |
| неправильный ProgID COM | `MVTU.Server` не существует; рабочий — `mmain.MVTU_Server` | перебор кандидатов: ProgID×2 + CLSID |

## 6. Рекомендации по дальнейшему развитию

1. **Пакеты проектов** (`OpenPack`/`Pack*`) — API уже есть в `Simulation`,
   нет демо-примеров и тестов. Добавить `examples/model4_pack.py`.
2. **Экспорт в XML и чтение сигналов по label из `.xprt`** — парсер меток
   сигналов из XML (см. `Tests/XMLReader`) повысит точность поиска сигналов
   после `ProjectStart`.
3. **Обход неработающих через COM классов блоков** («Из памяти», «Порт
   выхода») — генерация встроенного языка SimInTech (`createblock`/
   `createmodel`) из Python как резервный путь создания блоков.
4. **SDB (БД сигналов)** — интеграция с `sdb_adapter.py` из
   `simintech-connector` (Категория→Группа→Сигнал) для поиска сигналов по
   полному имени из БД.
5. **Перехват лога (`PipeLogger`)** — протестировать на Windows; добавить
   автоматическое включение в `SimInTechAgent`.
6. **Визуализация схемы** — рендер layout-модели в SVG/PNG для отладки
   алгоритмов (полезно для ИИ-агента).
7. **Слияние с `simintech-code-library`** — перенести паттерны встроенного
   языка (ПИД, RC, state-space) в `docs/` для документирования резервного
   пути создания блоков. *(Выполнено: `docs/simintech-language/`.)*
8. **Уточнить схему именования сигналов блоков в COM** — открытый вопрос из
   §1: `FindSignalData(name)` не находит сигнал по имени блока. Варианты
   решения: экспортировать модель в `.xprt` и извлечь имена сигналов из
   XML; спросить поддержку SimInTech; изучить `GetDataInfoFromList` на модели
   с блоками «Вход/Выход алгоритма».
